字段与分页

groups 的键是请求的规范化状态。每个状态 issues 和 total 与同条件 /api/issues?status=...&limit=...&offset=0 的结果逐字节一致；issues 完整沿用旧 compatibility Issue 字段、别名和 labels。空状态也保留。has_more = issues.length < total。

默认七个状态：backlog、todo、in_progress、in_review、done、blocked、cancelled。statuses/status 为逗号列表；open 规范化成 todo，重复状态去重。默认每状态 limit=50，上限 500，limit=0 返回空页及总数。仅支持 offset=0，非零 offset 返回 400；后续各状态继续调用旧 /api/issues。

include_archived_total=true 才输出 archived_total，并且只增加一条 COUNT；不传时没有这个字段、没有这次查询。该值是当前工作区全部归档 issue 的数量，独立于状态、project、assignee 等筛选，保持 archivedIssueCountOptions 原口径。

issues[] 的全部字段：id, workspace_id, number, identifier, title, description, status, priority, assignee_type, assignee_id, creator_type, creator_id, parent_issue_id, parent_done_grant_at, parent_done_grant_by, parent_done_grant_agent_id, issue_kind, source_issue_id, project_id, runtime_workspace_id, position, start_date, due_date, completed_at, archived_at, created_at, updated_at, metadata, labels。labels[] 字段：id, workspace_id, name, color, created_at, updated_at。类型、空值和序列化均沿用 packages/server/src/api/wire/issues.ts 的 issueCompatibilityResponse。

接口选择与一致快照

独立 compatibility 路由使旧列表响应形状保持稳定，也避免复用按 assignee 分组的 /api/issues/grouped。每状态保留现有 ORDER BY updated_at DESC + LIMIT/OFFSET 子查询，再组成一条 UNION ALL；统计一次 GROUP BY status，labels 一次批量水合。生成 SQL 分支随状态数增加，但执行查询次数保持常数，没有逐状态数据库往返。

选择 UNION ALL 是为了保留旧单状态 SELECT 的排序和截断，包括 updated_at 相同的记录；窗口排序可能改变相同时间戳时入选的记录。本轮没有为旧排序新增 ID tie-breaker。

SQLite 使用同一个读事务；PG 在事务内首次读取前执行 SET TRANSACTION ISOLATION LEVEL REPEATABLE READ READ ONLY。所有状态行、total、labels 与可选归档计数都在同一快照内。已有事务中的调用被拒绝，避免继承未知隔离级别。双连接 golden 在列表行读出后迁移状态、归档并删除标签，响应仍与变更前逐字节一致。

性能口径

同一份 fixture 每状态 120 条，七个状态，limit=50，归档 21 条；my-issues 使用同一 project 与 usr_ assignee。先预热一次，再采五轮，下面是各指标中位数。七次旧单状态请求与新请求使用完全相同的筛选；另列加入原归档请求的完整首页。

PG 的 dbq/db/dbb 直接读取真实 Server-Timing，包含鉴权、事务 BEGIN/COMMIT 和隔离级别设置；SQLite 的该计数器不计 SQL，故由驱动 probe 计实际语句（含 BEGIN/COMMIT）、驱动耗时和序列化结果字节。跨后端耗时不可直接比较。字节同时列 DB 返回字节和未压缩 HTTP JSON 字节。已包含 MUL-474 的 last_used_at 节流，不能拿节流合入前的数字混算。
