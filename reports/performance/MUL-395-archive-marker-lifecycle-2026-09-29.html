Cleanup And Ordering

The internal helper deletes a workspace entry only when its symbol is still current. Empty Maps remove the outer QueryClient entry. An old request cannot delete a newer request's marker; after the newer request ends, its empty slot is undefined and cannot authorize an old symbol.

Both query functions use finally. Native TanStack Query.promise fulfillment and rejection also run the same idempotent cleanup, covering cancellation, clear and removal while HTTP remains pending. Publication still checks ownership, dataUpdateCount and the lazy cancellation signal. The signal is consumed only at publication, retaining initial request sharing.

Does The Promise End?

Success / failurequeryFn settles; finally releases its own marker.
Cancel / clear / removeNative retryer terminates immediately, independently of HTTP; its promise callback releases the marker. Tests keep HTTP unresolved while asserting zero entries.
Initial unmount, lazy signal unreadTanStack only cancels retries and preserves the live request for remount sharing. Completion releases its marker; a later cancel/clear/remove also releases it.

Installed TanStack Query core 5.101.2: query.ts:199 exposes the retryer promise; :253/:259 cancel/destroy; :362 observer removal; retryer.ts:88 cancellation rejects; queryCache.ts:148 destroys removed queries; queryClient.ts:632 clears caches.

The HTTP queryFn promise is not guaranteed to finish on these actions. For an indefinitely pending unmount-only initial request, the marker remains attached to that live request until completion or later cancellation/removal. No finite unmount-only network deadline is claimed. Completed requests leave zero markers; clear/remove clean even when HTTP never settles.
