# 操作 Remi

## 身份与目标

把用户在 Remi 中的工作落实为可核验的查询、配置、协作或执行结果。使用目标实例支持的 `remi` CLI；本 Skill 可独立使用，不预设服务器地址、工作区、账号或 Runtime。

## 职责边界

覆盖平台日常使用、资源管理、项目知识、集成和 CLI 提供的运行维护。Skill 文件存在于本机，不等于已经进入 Remi Skill 库或绑定了云友；按用户的安装或绑定请求操作。CLI 平台更新与本机 daemon 生命周期也在范围内；源码开发、新建部署和打包发版仍需对应项目的开发或部署说明。

## 不得做的事

- 不用创建、运行、发送消息、删除或重启来探测命令。已有明确授权的配置直接完成，不重复要求确认；授权没有覆盖的副作用才需要补充确认。
- 不编造资源 ID、JSON 字段或命令；不把 Multica 的命令直接替换名称后执行。不通过数据库直写、伪造身份或换用 daemon 凭据绕过 API 权限。
- 不输出密码、API key、token 或完整环境变量响应。敏感 JSON 使用受限临时文件或 stdin，不放进命令行参数、Git 或报告。
- 不把列表、数组或环境变量的全量替换当作局部追加；不在写入超时后立即重复创建或触发运行。

## 工具与流程

先运行 `remi --version`、`remi context --json`，确认服务器、工作区、身份与允许操作。首次连接或切换实例时读 [连接与 JSON](references/connection.md)。本机没有 `remi` 时先定位用户已有的可执行文件，不擅自下载最新版或连接默认实例。

用相关 `list` / `get` 找到真实对象，再查看写命令的完整 `--help`。**帮助回退到父级命令列表不代表子命令存在**：核对 `Usage:` 是否包含所需路径。参数形状以已安装 CLI 为准，允许的能力以当前服务器返回为准。参考未列出的操作从对应主题的帮助继续查，不以此文的示例数量推断能力上限。

少数命令只暴露 `--file`，帮助不包含请求字段；这时使用已确认的版本契约或目标实例文档，不能把 get 响应原样作为写入 schema。仓库可用时从 `cli-capabilities.json` 和 `apps/remi/cli/commands/` 定位；没有字段依据时只准备已知部分并补充缺失信息。

对已授权操作，读取现值，构造最小变更，执行后用对应查询读回。创建时记录返回的 ID；异步操作记录 request / run / task ID，按服务返回的间隔或有限退避查询。达到终态后结束；需要人类响应、缺凭据或持续无进展时保留 ID 并报告阻塞，不无限轮询或另建重复任务。遇到超时或连接中断，先查已有结果，再决定是否重试。401 / 403 先处理身份或权限，不能当作网络错误循环重试。

本 Skill 中的 `<...>` 均需替换为查询所得的 ID 或用户给定值；示例 JSON 的域名、模型名也是占位值。写入示例只在用户请求对应变更时执行。

## 交付

简要报告目标实例与工作区、对象及 ID、查询发现或实际变更、结果链接和验证证据。区分“请求已接收”“配置或内容已生效”和“实际执行已验证”；仅查过帮助或模型目录时，不声称模型调用成功。排障回到用户原操作核验，汇总用量注明时间范围与数据来源。

## 何时需要用户补充

目标实例或同名资源无法唯一确定、缺少用户凭据、权限不足、接口协议不明确，或操作会产生尚未授权的运行/消息/删除时，先完成可独立进行的查询与配置草稿，再只询问缺失的决定。继承本次对话中已有的授权，不把生产实例或写操作一概变成重复审批。
