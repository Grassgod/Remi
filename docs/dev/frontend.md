# 前端开发上下文

规则见[前端 AGENTS.md](../../frontend/AGENTS.md)，环境和统一命令见[仓库开发入口](../../CLAUDE.md)，其他领域从[开发索引](README.md)进入。本文记录当前源码结构，不代表已启动服务或完成性能验证。

## 当前结构

前端属于[根 Bun workspace](../../package.json)，当前应用目录只有 `frontend/apps/web/`。`@multiremi/*` 是现有包名；包导出直接指向 TypeScript 源文件，由 [Next.js 配置](../../frontend/apps/web/next.config.ts)的 `transpilePackages` 编译。

前端从 `@multiremi/contracts` 根入口只能 `import type`；运行时的值走[子路径导出](../../packages/contracts/package.json)（如 `@multiremi/contracts/issue-activity`）。根入口是 `export * from "./x.js"` 的汇总，webpack 无法解析这些 `.js`，值导入会让 `next build` 失败，而单测和 `tsc` 都发现不了。[架构测试](../../tests/arch/frontend-contracts-root-imports.test.ts)会拦截这类导入。

## 页面启动与工作区

1. [根 layout](../../frontend/apps/web/app/layout.tsx)加载语言资源、主题与 `WebProviders`。
2. [WebProviders](../../frontend/apps/web/components/web-providers.tsx)注入 API/WS 地址、导航和语言适配器。当前显式使用 token 认证（`cookieAuth = false`）。
3. [CoreProvider](../../frontend/packages/core/platform/core-provider.tsx)初始化 `ApiClient`、认证和聊天 store，挂载 `QueryProvider`、`AuthInitializer`、`WSProvider`。
4. [工作区 layout](../../frontend/apps/web/app/%5BworkspaceSlug%5D/layout.tsx)从 URL slug 解析工作区，再调用 `setCurrentWorkspace(slug, id)`；它同时控制认证、加载和无访问权页面。当前不强制经过旧 onboarding 向导。
5. [workspace-storage.ts](../../frontend/packages/core/platform/workspace-storage.ts)维护 slug/id 对及持久化命名空间，通知 WS 和 store 重载。请求头由 [HttpClient](../../frontend/packages/core/api/http.ts)读取当前 slug 生成。

相对时间的首轮 SSR 与浏览器接管使用 RootLayout 传入的同一时间快照，由 [HydrationTimeProvider](../../frontend/packages/views/i18n/hydration-time.tsx) 提供。共享 `useTimeAgo` 在每个流式子树完成接管后使用浏览器当前时间；跨分钟、小时或天边界不会因首帧文本不一致重建日志和重新读取图片。

API 代理目标由 [resolveRemoteApiUrl](../../frontend/apps/web/config/runtime-urls.ts)解析；[next.config.ts](../../frontend/apps/web/next.config.ts)配置 `/api`、`/ws` 等代理路径。改连接配置时同时核对服务端代理目标和浏览器侧 `WebProviders`，不要只改其中一端。

Issue 详情页由 [server-log.ts](../../frontend/apps/web/features/issues/server-log.ts)在 800ms 预算内用 httpOnly cookie 读取详情、会话、最后 30 条日志、seq 0 和 `/api/turns?issue=...` 轮列表，注入同一棵 React 查询缓存；失败时只输出外壳，由 Bearer 客户端补齐。`?comment=<id>` 先经 `/log/locate` 找到所属会话与 seq，再取前后各 15 条的锚点窗口。轮列表同时供底部运行条和上方 `AgentLiveCard` 的首帧使用；运行卡片按实际内容占高：有 SSR/查询缓存时直接首绘，缓存缺失时首个轮状态读取也作为揭示的布局门禁，结束（含失败）后才显示日志；后续 reconcile、订阅者和本地目录资源仍在揭示后处理，底部运行条在揭示后挂载并作为运行场景实际终点。尺寸已固定的图片不阻塞揭示；日志无尺寸图片由 SSR 和客户端统一预留 240px 固定框，晚到与失败都不改变行高，详见 ADR 0008。浏览器仍使用 Bearer 请求，不开启 cookieAuth；[IssueLogReplica](../../frontend/packages/core/session-log/issue-log.ts)把 SSR 窗口导入本地副本后继续订阅日志流，深链窗口两端按需分页，回到最新时换回尾部窗口。`body_html` 只消费服务端预渲染结果，缺失时由原客户端 Markdown 路径降级。

Issue 的说明与评论区之间保留横向分隔，评论使用独立边框卡片。`AgentLiveCard` 通过 `SessionLogList.afterRow` 放在说明行之后、与其他日志行同级，吸顶范围覆盖整个评论滚动内容；不能再把它嵌入单个日志行或固定高度的 `overflow-y-auto` 占位。没有活动任务时不留空盒子；多任务展开按内容占高，列表最多占半个视口并可滚动。旧会话或旧请求的迟到结果不会改变当前访问的显示门禁。缓存缺失时以一次首个状态读取替代永久的 128px 预留，不用提高揭示预算或放宽可见跳动门禁。日志头移出的控件及评论新内边距使用 `issue-cards-v2` 行高缓存版本，避免复用旧的 128px 占位或平铺行尺寸。真实几何回归在 [zero-jump-check.ts](../../tests/integration/zero-jump-check.ts) 的 `detail-layout` 场景覆盖桌面、手机、滚动吸顶及展开，`detail-running-empty-cache` 覆盖晚到状态与首屏锚点。

Issue 属性侧栏的工作位置通过 [WorkLocationPicker](../../frontend/packages/views/runtimes/components/runtime-workspace-picker.tsx) 的 `wrapLabel` 模式占满属性值列，长项目名和本地目录名称按可用宽度换行；有任务而禁止改位置时也保留完整名称。Chat 与创建 Issue 的紧凑选择器沿用默认的单行截断。

## 统一消息与轮展示

Issue 与 Inbox 的对话消息头使用 [MessageHeader](../../frontend/packages/views/common/message-header.tsx) 显示收件人/角色、message_kind 与实际 wake_applied，wake_reason 用作提示；未知显示枚举保留原字符串。Chat 不渲染消息头，只在用户消息的 wake_applied 存在且不是 `now` 时，用 `messages.wake_reasons` 的文案显示一行未唤醒提示。Issue 与 Chat 优先识别 canonical 消息头，保留的 metadata.envelope 不会把正常消息变成系统详情。Chat 乐观发送以 canonical dedupe_key 匹配日志行；日志确认后只显示服务端正文，编辑替换正文，删除或隐藏不会复活本地草稿。Issue 与 Chat 的轮行消费服务端从 multiremi_turns 投影的卡片，卡片不自行制造工作轮或用户消息。

Chat 列表和详情的未读数来自创建者对应的 workspace member lane：只计 cursor_seq 之后、发给该成员且 shown/未删除的消息。自动已读经统一 inbox/read 推进同一游标，随后刷新会话列表保持已读；新消息到达后才再次标读。

Issue 轮行的 [TurnControls](../../frontend/packages/views/common/turn-controls.tsx) 展开时才读取 attempts，查看日志时传选中 attempt_id；历史日志与当前尝试独立。失败/取消轮可以暖重试或冷重试，服务端返回同一 turn.id 和新的 current_attempt_id。Chat 不显示尝试列表。终态的 Chat 轮有一张卡和一条回复消息（`final_entry_id`），卡在前；[chat-message-list.tsx](../../frontend/packages/views/chat/components/chat-message-list.tsx) 在回复已加载时去掉卡行，由回复行承载结果，避免失败原因重复。失败/取消轮由 `TurnEndNotice` 显示状态与失败原因、「重试」「在新会话中重试」（`api.retryTurn(turnId, cold)`，走服务端的 Chat 创建者路径，失效与 TurnControls 相同的查询）和以该轮 attempt_id 懒加载的执行记录按钮；没有回复的轮（如取消）由卡行显示同样的提示。已完成轮不显示状态文字；卡片 `metadata.process_item_count > 0` 的轮在回复（或失败提示）上方显示折叠的执行步骤，执行记录按钮在折叠里，其他轮的执行记录按钮在回复下方，悬停或键盘聚焦时显示。两者都在点击后才读取任务与 trace。输入弹窗按需读取 turn input 的完整 `(from_seq,to_seq]` 消息与 legacy_prompt，不在首屏逐行展开。

Chat 独立页是 [ChatWindow](../../frontend/packages/views/chat/components/chat-window.tsx) 的 `page` 呈现：没有 PageHeader，会话头显示 Agent、标题与绑定位置（目录名只在会话绑定目录时读取），首次读取日志超过 400ms 才显示 28px spinner；浮窗头部保持「⊕」与 [SessionDropdown](../../frontend/packages/views/chat/components/session-dropdown.tsx)。左栏是 [ChatSidebar](../../frontend/packages/views/chat/components/chat-sidebar.tsx)：`groupChatSessions` 把未归档会话分成置顶、Project/Runtime 目录分组和最近（绑定位置的会话不进最近），`visibleItems` 实现 10 / 5 组 / 每组 5 条的分页与「只隐藏 1 条就全显示」，当前会话始终可见。侧栏显示期间读取自动化列表（「自动化」入口的未读圆点）和 `pendingChatTasksOptions` 聚合；聚合项带 `turn_id`，停止运行按 turn 调用 cancel；服务端在 turn 列表里给出 `running_subagents` 时，运行中的行在转圈旁加「N 个子代理」，字段缺失（旧服务端）或为 0 时只转圈，`task:subagents` 事件用 `setQueryData` 改写聚合里对应项，不重新请求，也不触发 `task` 前缀的通用刷新。会话列表项带 `running_background_tasks`（PR 6，会话级后台任务数，含轮结束后仍在跑的）时，行上显示「N 个后台任务」：没有运行中的轮也显示，旁边是小圆点（有新回复时是未读圆点）而不是转圈；有运行中的轮时仍在转圈旁，子代理数优先；字段缺失或为 0 不显示。`chat:background_tasks` 事件改写所有会话列表和详情缓存里的计数。归档或删除有后台任务的会话会停止它们，所以归档没有运行中的轮也先确认，删除确认里多一句「它的 N 个后台任务也会停止」。运行时目录列表只在有会话绑定目录时读取。行操作复用 `useUpdateChatSession` / `useDeleteChatSession`，失败统一 toast `sessions.failed`；删除沿用工作区切换与新选择保护。右键与「⋯」共用一个 DropdownMenu（嵌套的 Base UI 菜单根会变成子菜单）。折叠和移除用 motion 300ms `cubic-bezier(.19,1,.22,1)`，减少动态效果时时长为 0；长标题渐隐、悬停 350ms 后按 28px/s 滚动，减少动态效果时不滚动。全局搜索 [search-command.tsx](../../frontend/packages/views/search/search-command.tsx) 的「聊天」分组只在面板打开时查询 `chatSessionsOptions`，按标题匹配，最多 9 条。

Chat 消息区通过 [SessionLogList](../../frontend/packages/views/common/session-log/session-log-list.tsx) 的 `contentClassName` 使用 768px 主栏（Issue 保持默认），`scrollButton="arrow"` 在解除跟随且离底超过 24px 时显示 32px 圆形回到底部按钮并以新消息数作角标（内容不足一屏时上滚不会留下按钮），Issue 仍用新消息 chip；离底判定沿用 `useStickToBottom` 默认的 24px。用户气泡最宽 70%、圆角 22px，行间距 12px；Chat 行的 `render_version` 追加 `:chat-layout-v2`，旧布局的行高缓存不再命中。复制、执行记录等消息操作在悬停或键盘聚焦时显示，复制成功图标变为对勾 1500ms。回归见 [侧栏测试](../../frontend/packages/views/chat/components/chat-sidebar.test.tsx)、[消息列表测试](../../frontend/packages/views/chat/components/chat-message-list.test.tsx) 和 [ChatWindow 页面测试](../../frontend/packages/views/chat/components/chat-window-project.test.tsx)。

Chat 输入框运行中有两种后续发送方式（[ADR 0020](../adr/0020-chat-follow-up-queue-and-native-steering.md)）：引导走统一消息接口并显式发送 `wake_requested:"now"`，排队走 `POST /api/sessions/:id/queue`。默认方式是 `useChatStore.followUpMode`（全局键 `multimira:chat:followUpMode`，默认 steer），在设置的「偏好」→「聊天」中修改；[submit-shortcut.ts](../../frontend/packages/views/editor/extensions/submit-shortcut.ts) 让 ⌘↵ 按默认方式提交，IME 组字期间不提交。⌘⇧↵ 以 `invert` 换用另一种方式，只在传 `invertibleSubmit` 的编辑器（目前只有 Chat 输入框）绑定，其他带 `onSubmit` 的 `ContentEditor` 不绑定该键，行为不变；空闲时都是普通发送。运行中主按钮的 aria 与图标随方式变为「引导」（ArrowUp）或「排队」（ListPlus），title 同时列出两种快捷键。排队先在 store 的 `queueOutbox`（按工作区持久化）中显示本地行；没有 API 应答的失败（网络错误、超时、网关 408/502/503/504、无法解析的应答）保留为「无法确认送达」，从不自动重试，重试复用同一 `client_id`，服务端列出该行后本地行消失；其他状态的拒绝移除本地行，首次入队时草稿留在输入框，重试被拒（归档、队列已满等，`queued_message_deleted` 除外）时正文和附件绑定放回输入框（编辑中则接到暂存草稿后）。归档与队列已满有专门文案。队列 mutation 使用 `networkMode: "always"`，离线时立即失败为「无法确认送达」而不是挂起；切换工作区后才返回的入队，成功或被拒时从原工作区的存储中移除。入队返回 `released` 时刷新会话日志；入队前先发出撤销窗口内的删除，因为空闲 lane 的入队会放行全部 queued 条目。停止当前轮后刷新队列，服务端因 `interrupted` 暂停队列。删除会话时清除该会话的 `queueEdit` 与 `queueOutbox`。

[ChatQueue](../../frontend/packages/views/chat/components/chat-queue.tsx) 只在可见 Chat 中挂载（MUL-472），读取 `chatQueueOptions`（键 `["chat", wsId, "queue", sessionId]`）；`chat:queue_updated` 和 pending turn 变化使其失效，有条目或暂停时以 10s 兜底轮询，标签页隐藏时停止。列表最高 30dvh，每行一行预览（空白折叠），预览可聚焦，悬停 700ms 或键盘聚焦显示全文；行的 aria-label 为位置与最多 80 字符（含省略号）的预览，引导、重试和「⋯」按钮的可访问名称带位置。行操作是「引导」（`POST .../queue/:qid/steer`，提示「提交，但不中断模型运行」）和「⋯」菜单的编辑、删除；进行中的 steer/PATCH/DELETE 由 `useMutationState` 显示 spinner、透明度 0.6 并禁用删除。`send_failed` 的行显示警告、重试（resume）、编辑、删除；409 `queued_message_consumed` 用 toast 说明已发送。归档的 Chat 中引导、继续和重试保持可聚焦但不执行，提示先恢复会话；编辑、删除照常。删除先隐藏并给出 5s 撤销 toast，到期时先关闭 toast 再调用 `DELETE`（之后点撤销提示已无法撤销），卸载或切换会话时立即发出；继续（resume）和失败行的重试先等撤销窗口内的删除完成。撤销期间条目若离开列表，立即发出 `DELETE`：已被轮放行时 409 并提示「在删除前已经发送」，已在别处删除时静默。删除后焦点移到下一行、上一行或输入框。暂停横幅区分 `interrupted` 和 `turn_ended`，客户端在 lane 空闲、未暂停却仍有 queued 行、且数据读于最近一次 turn 变化之后时，宽限 2s 后显示「尚未发送」横幅；横幅锁定在条目、暂停与 turn 不变期间，后台刷新不使其闪烁。三者都可「继续」（resume）。编辑把条目正文和按 `/api/attachments/<id>/` 重建的附件绑定载入输入框，当前草稿暂存在 `useChatStore.queueEdit[sessionId]`（按工作区持久化），同时只能编辑一条；输入框显示「正在编辑排队消息 · 取消」，主按钮为「保存」，Esc（组字或 @、/ 建议打开时除外）取消并在输入框处截停，输入框保持焦点。保存以 `expected_revision` PATCH 后恢复暂存草稿；条目已发送、已删除或版本冲突时，提交的文本留作普通草稿（暂存草稿接在其后）并退出编辑，toast 分别说明已发送、已删除或已在别处修改；编辑中的条目从列表消失时说明「已发送或已删除」。其他失败保留编辑状态。

日志中被发送人删除的未读消息，其删除帧的 `fields.deleted_at` 会立即移除副本显示行并保留 revision 水位；IssueLogReplica 以 C7 快照决定行是否存在，只为仍在快照中的行保留已补齐的显示字段，避免旧窗口合并回已删正文。HTTP/SSR 窗口导入完成后才应用完整快照，避免 seq 0 和正文分批写入时丢失首屏行；live entry 的成功回读若已找不到该行，则传递最小隐藏标记，保留同批其他帧，网络与接口失败仍上报错误。每次日志写入都会递增 `log_version`（产生该帧的写入也算），所以 live entry 的回读通常比已加载窗口新，版本不同不作为拒绝理由，新旧由行 revision 判断；版本变化也不丢弃进行中的回读或已读窗口。页面在拿到 Web Lock 前打开副本时，follower 阶段的窗口写入没有 leader 应答，本页成为 leader 后自行补写，否则 ack 后 C7 快照会裁掉 SSR/HTTP 窗口里本地库还没有的行；leader 也为 follower 读取从 seq 0 开始的显式窗口，读其他会话的范围时不复用本会话已读窗口。重连重放或刷新回填的旧行不能恢复正文，主消息区也过滤带 `deleted_at` 的 canonical 消息。Chat 页每次发送都会替换 `?session=` URL（首条消息导航到刚创建的会话），路由随之重新读取日志 bootstrap；ChatWindow 只用会话首次显示时已有的 bootstrap 播种日志，同一会话之后到达的 bootstrap 不再重建副本，避免发送途中换成更早的读取并丢失刚发送的行和回复。回归见 [ChatQueue 测试](../../frontend/packages/views/chat/components/chat-queue.test.tsx)、[输入框测试](../../frontend/packages/views/chat/components/chat-input.test.tsx)、[ChatWindow 页面测试](../../frontend/packages/views/chat/components/chat-window-project.test.tsx)、[ChatWindow 日志链路集成测试](../../frontend/packages/views/chat/components/chat-window-log.integration.test.tsx)和 [IssueLogReplica 测试](../../frontend/packages/core/session-log/issue-log.test.ts)。

决定抽屉按需读取 `/api/issues/:id/questions` 的统一原 Q 投影；[共享问题卡](../../frontend/packages/views/common/question-card.tsx)显示原问题、独立 Remi 总结、来源、当前处理者、路由版本和重新路由/回答历史。人工阶段标为「待回答」；交给 Agent 时标为「等待 X 回答」并只读，提示由 Agent 处理、答不了会继续上交；问题在根单之前进入人工阶段时按 `route_reason` 说明原因，并链接到需要配置执行负责人的 Issue。Issue 主线、Chat 通知、Inbox 和运行中的问题 dock 沿 `metadata.question` 或 `root_question_id` 读取同一个 Q，答复使用版本校验的 `/api/messages/:id/question/answer`，最终由服务端写回原会话。原权限提问同样读取 Q，保持单选并提交原 `option_id`；原上下文单独按 Markdown 折叠展示。表单失败保留输入；`wait_status` 区分原调用等待、已结束、已消费与续接消费，不能把答案保存成功写成恢复成功。未知展示枚举保留原值。答复遇到 `409 question_route_changed` 时，问题卡重读该 Q；当前成员仍可执行同一操作且答案版本未变，就用新路由版本自动重交一次，否则与 `question_answer_revision_changed`、`question_already_settled` 一样显示本地化说明，不显示错误码。人工阶段的每个提醒对象各有一条 `question_notification`；Issue 时间线只为发给当前成员、且原 Q 不在同一会话的那条提醒渲染问题摘要，原 Q 在同一会话时只显示原 Q 行（提醒带 `source_question_session_id`；旧的待恢复通知没有它时，以已加载的原 Q 行判断）；Chat 的成员提醒与原 Q 同在一个会话，Chat 时间线不渲染成员提醒，只显示原 Q 行。同一问题不重复出现。

运行卡片（[HumanRequestDock](../../frontend/packages/views/common/human-request-dock.tsx) 与 [LinkedQuestion](../../frontend/packages/views/common/linked-question.tsx)）为每个问题显示一行摘要：状态标签「待回答」（橙色）、「等待 X 回答」（蓝色）或「已回答」（附回答人与答案摘要），问题标题，以及「回答问题 ›」或「查看 ›」按钮。点击打开右侧 720px 的 [DecisionPanel](../../frontend/packages/views/common/decision-panel.tsx) 抽屉；它是独立浮层，不占用属性栏，按待回答、等待 Agent 回答与已回答/已关闭分节，复用问题卡作答。Issue 顶部蓝色提示条只在详情的 `pending_decision_count` 大于 0 时显示「N 个问题待回答」和「回答问题」，该计数只含本单人工阶段的待答问题；黄色依赖等待条不变。提示条打开的 [Issue 问题抽屉](../../frontend/packages/views/issues/components/issue-decision-panel.tsx)描述里的计数与提示条同一口径；本单待回答问题在前，子 issue 的待回答问题单列一节，再是等待 Agent 回答的问题，已回答与已关闭默认折叠；抽屉打开期间，刚答完的问题留在原位显示结果。Issue 详情侧栏只保留属性、父/子 issue 等区块，没有责任模块、常驻的问题历史入口、交付卡或根人类选择器；属性里的执行指派显示为「执行负责人」。状态选择器可以直接改成 `done`，没有交付验收或 parent-done grant 控件，是否允许由服务端的 done 规则决定。新建与快速新建不选择人类，设置页没有历史责任映射页；飞书 bot 设置里的成员只是无 Issue 的 Chat 问题处理人，topic 与自动化设置不要求人类责任人。这些文案由 [执行文案测试](../../frontend/packages/views/locales/issue-execution-copy.test.ts) 守护：除 onboarding 模板外不出现验收、指定人类、正式交付一类文案，并固定「执行负责人」「待回答」「等待 X 回答」「已回答」「回答问题」「查看」「N 个问题待回答」。

评论与会话日志的 [EntryHtml](../../frontend/packages/views/common/session-log/entry-html.tsx) 会把服务端 `div[data-type="fileCard"]` 增强成统一附件卡片。静态 [entry-html.css](../../frontend/packages/views/common/session-log/entry-html.css) 在首屏给每个槽位预留固定 40px（32px 卡片加上下各 4px 间距），普通和紧凑密度共用；图片与 HTML 文件也保持卡片外观，预览在弹窗中打开。附件记录通过 `attachments` 传入 provider，预览与下载按附件 ID 走现有链路；没有记录时使用 URL 模式，不合法 href 只显示文件名。

客户端 [file-cards.ts](../../frontend/packages/ui/markdown/file-cards.ts) 与服务端 [preprocess.ts](../../packages/server/src/render/preprocess.ts) 同步接受 `/api/attachments/<id>/content`，ID 限 `[A-Za-z0-9_-]`，可选查询串不得含 `)`、空白或 `..`。API href 必须整串精确匹配。Chat 直接交给共享 Markdown 渲染，两处附件列表显式使用 `dedupe="url"`：正文内联 URL 不再追加独立卡片，不同 URL 即使同名、同类型、同大小也各自保留并按各自附件 ID 下载。评论使用默认 `dedupe="file"`，保留按文件名、类型、大小隐藏重复上传的现有行为。MUL-518 保持 `RENDER_PIPELINE_REVISION = 1`；已有正文重渲染所需的版本提升由 MUL-513 负责，在其游标与节流回填就绪后处理。

日志中的 HTML 附件预览由 `DeferredContentContext` 延迟到实际揭示后读取，揭示前只显示固定槽位（默认 240px，已有 QueryClient 高度缓存时复用）。成功、错误与重挂载保持槽位高度；日志外的预览保留原高度和错误展示。正文、工具栏、弹窗和独立预览页共用带 workspace slug 与附件 ID 的内容 query key，保留 5 分钟 staleTime、30 分钟 gcTime、无自动重试及既有失效策略。SSR 播种的日志需等定位脚本确认 DOM 已揭示才启动这些可选读取。运行任务卡片使用 128px 可滚动槽位，避免缓存缺任务时后续卡片增高移动日志锚点。

SDK 的直接 AUQ 题项与 ACP 的 `{fieldKey, question}` 题项在展示表单层统一解析，原 Q 的 payload 保持原样；两种形式都支持多题、多选和自由回答。
执行归属选择器只提供 Agent／Squad。历史 member 执行指派保留原身份并明确标为待配置；新建单不会继承旧 member 项目默认值。

执行记录是 turn + items（PR 2）：一次尝试一个 `TraceTurn` 加若干完整的 `TraceItem`，契约在 [contracts/trace.ts](../../packages/contracts/src/trace.ts)。页面、Daemon 和飞书用同一个 reducer [turn-trace.ts](../../packages/shared/src/turn-trace.ts) 折叠：按 `id` upsert 并保留首次出现顺序，`item.delta` 只在条目进行中且 `seq` 更新时追加，重放页面 `head` 之前的事件不改变状态。读接口 `GET /api/turns/:id/trace?view=turn&item_cursor=` 按条目游标分页，[schemas/tasks.ts](../../frontend/packages/core/api/schemas/tasks.ts) 的 `TraceTurnPageSchema` 逐条丢弃不合契约的条目；socket 帧用判别联合 `TraceEventSchema` 解析，未知类型跳过。v1 文件返回 `format: "legacy"`、无 turn 无 items，各读取方都不显示内容也不加标签。

[useTurnTrace](../../frontend/packages/views/common/task-transcript/use-task-trace.ts)`(attemptId, { enabled, live, turnId })` 是唯一的浏览器读取方，返回 `{ turn, items, closed, loaded, error, retry }`。查询键保持 `["task-trace", attemptId]`（MUL-472 守卫与 chat-done 失效依赖它），缓存值是 reducer 状态：一次读取取完所有页，每页到达就写入缓存（首次读取时条目逐页出现，读取完成才算 `loaded`），读取进行中收到的帧在页之后重放；`stream.gap` 或 hub 已无法覆盖到已读 `head` 的 ack gap 会重读快照并替换状态，`stream.closed` 封闭。读取完成后再打开的订阅从 `head + 1` 开始（`subscribeTrace` 的 `fromSeq`），可见性切换不会重放 hub 的整段缓冲。实时读取方 `staleTime` 为无穷；非实时读取方在快照未封闭时挂载即重读。chat-done 只把该键标记为过期（`refetchType: "none"`），不立即重读多页记录。最终回复是 `phase: "final"` 的顶层条目，工具数是 `turn.stats.tool_call_count`（运行中按同一规则从条目计算），模型和上下文占用来自 `turn`。

执行模型优先读取 trace 的 `turn.model`（bridge 最后上报的主模型，子代理的模型变化不进入 turn），忽略空值和默认占位值；它随 reducer 状态更新，切换任务换查询键即清空。缺少有效模型时依次使用任务执行配置、Agent 配置；混合计费用量包含进度摘要等辅助调用，不能据此推断执行模型。上报模型与任务配置不一致时不借用该配置的推理级别；备用模型切换原因保持任务自身记录。实现和回归入口为 [execution-model-info.tsx](../../frontend/packages/views/common/task-transcript/execution-model-info.tsx) 与 [task-trace-dialog.test.tsx](../../frontend/packages/views/common/task-transcript/task-trace-dialog.test.tsx)。

执行过程弹窗打开时经 `useTurnTrace` 读取全部条目，任务仍在运行时订阅 trace socket；与 Chat 共用缓存，同一尝试的读取和帧只有一份。条目按 `parent_id` 嵌套：一次遍历建立顶层列表和父→子索引（子条目没变的父条目沿用原数组），子代理行收起其子条目，没有父条目的条目留在顶层。显示与复制前经 `redactItem` 脱敏（文本、输出、命令、输入、diff），id、状态和时间不变；结果按条目对象缓存在 `WeakMap`，reducer 不改动的条目保持同一对象，所以实时帧只重新脱敏并重渲染它改动的行（行组件用 `memo`，[规模测试](../../frontend/packages/views/common/task-transcript/agent-transcript-dialog-scale.test.tsx)覆盖 2000 条）。筛选只作用于顶层条目；计划区读 `plan` 条目；已结束任务里仍标为进行中的条目显示为未完成。切换任务换查询键，旧请求不能写入新任务；订阅被拒提供重试。

Issue 运行条读取已有任务状态、耗时和 `progress_summary`，详细 trace 在点击后读取；不为显示运行条自动下载历史记录。已结束的 Chat 直接展示会话日志保存的最终答复、附件和失败信息；复制正文取 `final_reply_md`，不依赖 trace 是否在线。分享页展开任务后读取全部条目，每个条目一行，文案与 Chat、飞书共用 [trace-step-copy.ts](../../packages/shared/src/trace-step-copy.ts)。

Chat 执行步骤（Codex 风格）由 [turn-steps.ts](../../frontend/packages/views/chat/lib/turn-steps.ts) 从条目计算：过程是除最终回复、`user_message`、`permission`、`question` 之外的顶层条目；命令每个解析动作一行（键 `${id}:${i}`），文件改动每个文件一行，网页搜索和其他工具各一行；思考不出行，只供运行中的状态文字；中间说明、上下文压缩、子代理、计划和提示打断分组。给子代理发消息、打断、恢复、关闭、列出子代理的工具调用是控制动作行（由 shared 的 `agentControl` 从工具名和输入推导，目标按 `thread_id`、`name`、id 解析成子代理名，像 id 的未解析目标读作「子代理」），分组摘要为「给子代理发了消息」或「管理了子代理」；Codex 的 `wait` 是隐藏步骤，不出行也不计入过程条目。连续两行及以上成组、默认收起，摘要按「文件变更 → 文件探索 → 命令 → 网页 → 其他」拼接，分隔符是各语言的 `turn_steps.summary_separator`（zh「，」、ja「、」、ko/en「, 」，en 后续片段用小写的 `_rest` 词条），数量只选单复数。词条在 `chat.json` 的 `steps`，zh-Hans 必须等于 `STEP_COPY_ZH`（[一致性测试](../../frontend/packages/views/locales/step-copy-parity.test.ts)）。

- 状态条 [task-status-pill.tsx](../../frontend/packages/views/chat/components/task-status-pill.tsx) 只说执行步骤说不了的：trace 还没有 turn 时（排队、派发、离线、重连、等待本地目录、准备摘要），实时读取失败或 trace 是旧格式时，以及等待人工时（`pendingTask.status === "awaiting_human"` 或最后一个顶层条目是进行中的 `permission`/`question`，此时为静态文案，先于条目判断，turn 的输入条目不会把它改成运行中）；其余运行期间隐藏。等待本地目录时，若原因（`wait_reason`，turn 列表的 `local_directory_wait_reason` 与 `task:waiting_local_directory` 都带它）由 `readBackgroundFolderHolder` 读出另一个对话的后台任务正占用共享文件夹，改为「本地文件夹正被另一个对话的后台任务占用」，该对话在读者自己的会话列表里时附「打开「{{title}}」的后台任务」，切到它的后台任务视图，不在时只显示这句，不带 id 和链接；原始原因（路径、id）从不显示，服务端写的进度摘要也不带会话 id。阶段取最后一个顶层条目：进行中的命令、编辑、网页搜索各有文案，进行中的回复为「输入中」，其余为「思考中」。失败或取消的轮折叠里不再放执行记录按钮，由失败提示提供。

## 验证入口

浏览器本地副本在 [replica/browser.ts](../../frontend/packages/core/replica/browser.ts)。Web Lock、BroadcastChannel、OPFS SAH pool 名和目录都使用同一个 `(user_id, workspace_id)` 分区键；频道消息再核对该键。leader 持有 Worker 和 socket，follower 通过频道查询；没有 OPFS 或 Web Locks 时，每页的 Memory 副本复用同一个 leader 请求队列和同步语义。

页面句柄显式 open/close，每个 tab 对同一 session 只声明一次兴趣；leader 按 tab 去重，最后一个 close 才退订。新 leader 宣告接管后，各存活页面重新声明，cursor 来自数据库的连续 head。dispose 终止 Worker 并结束 Web Lock 回调，使下一页可以接管。

副本 schema v3 包含 `revision_watermarks`，Memory 也保存同样的 `(session_id, seq) → revision` 水位。删除或隐藏只移除展示行，不移除水位；浏览器 log 出口的最小隐藏标记只带 session_id、seq、revision 和 visibility，同 revision 也移除已缓存正文，仍记录 coverage 并推进连续 head，不生成展示卡片或重复补洞。流帧和 HTTP 窗口都拒绝不高于水位的 revision，交接重开后仍有效。水位随删除行数增长，不按 coverage 回收；session 重置、身份切换和整库清除同时删除水位；`log_version` 变化不是重置，水位保留。旧版缓存无法还原已丢失的删除 revision，因此按既有 schema_upgrade 路径清库并重新同步。

Worker 请求带 session 生命周期令牌和清库代次，窗口查询带唯一请求 ID。close、dispose、clear 使旧请求失效；清库从任意页转给 leader，删除全部表内容及旧 meta，并广播 cleared。仍挂载页面的引用计数保持连续，清后新数据可以重建副本；logout 的授权和 socket 退出由调用方处理。ack 的新鲜度传到所有页面。ack 是续传（ADR 0007）：服务端每次日志写入都递增 `log_version`，版本变化只更新新鲜度令牌，不清空会话、不重置 cursor，已存的行与水位保留；逐洞补读等 Worker 写入确认后再响应。原夹具及 [QA 回归](../../tests/integration/replica-fixture/qa-run.ts)使用 C0 mock socket 和真实浏览器资源；离线场景在服务端订阅数为零之后追加数据。
