# Chat

Chat 是用户与一个 Agent 的持续私聊。可以直接提问、讨论或要求执行工作，无需先创建 Issue。
独立页面位于 `/<workspaceSlug>/chat`，与其他页面的浮窗共享会话选择和草稿；独立页不再挂载浮窗。
页面可以通过 `?session=<id>` 打开已有聊天，或通过 `?agent=<id>` 开始新聊天。在页内切换或新建聊天只改写地址栏，不重新加载页面，也不新增浏览器历史记录；刷新或分享该地址打开同一个聊天。

## 页面与侧栏

独立页没有页头横幅。会话头显示 Agent 头像、会话标题和已绑定的工作位置（Project 或 Runtime 目录名）；新聊天和历史都在左侧栏。浮窗保留原来的「⊕」按钮和会话下拉。会话有子代理或后台任务记录时，会话头右端（浮窗是右上角按钮组的最前面）多一个「查看子代理与后台任务」按钮，见下文「子代理」的「入口」。

桌面上左侧栏可拖右边缘调宽：默认 300px，最窄 240px，最宽 520px，且右侧对话至少留 480px（应用导航展开时更早封顶）；双击边缘恢复 300px，聚焦边缘后可用方向键调整。会话头左端的「隐藏侧边栏 / 显示侧边栏」按钮或 Cmd/Ctrl+B 隐藏和显示侧栏（焦点在输入框里时 Cmd/Ctrl+B 仍是加粗）。宽度和隐藏状态按浏览器记住。窄屏仍一次只显示列表或对话。

应用导航（工作区、搜索、新建 issue 及各页面入口）底部的「收起侧边栏」把它收成只有图标的窄栏，悬停图标显示名称；「展开侧边栏」或点导航右边缘恢复。收起状态按浏览器记住，所有页面通用。

侧栏顶部是「新聊天」和「搜索」，「搜索」打开全局 Cmd+K。可滚动区按「置顶 / 项目 / 最近」分区：

- 置顶会话只出现在「置顶」，不论绑定在哪里；
- 绑定 Project 或 Runtime 目录的会话只出现在对应分组，不在「最近」重复。分组按其中最新的会话排序，先显示 5 组、每组 5 条；
- 「最近」是没有绑定位置的会话，先显示 10 条。

「显示更多」每次加 10 条；只会隐藏 1 条时直接全部显示。分组标题悬停时出现「+」，新聊天直接带上该 Project 或目录。

每行只显示 Agent 头像和标题，不显示时间和第二行；运行中显示 spinner（这一轮有子代理在跑时旁边加「N 个子代理」），有后台任务在跑时显示「N 个后台任务」（见下文「后台任务」），等待人工回答显示「待回答」，有未读回复显示蓝点。悬停或键盘聚焦时，状态位换成「置顶」（已置顶的为「取消置顶」；「已归档」列表里为「恢复」）和「⋯」菜单；右键打开同一个菜单：重命名、置顶或取消置顶、停止运行（仅运行中）、归档（「已归档」列表里为恢复）、删除。

- 运行中或有后台任务在跑的会话归档前要确认，因为归档会在服务端停止这一轮和它的后台任务；空闲会话直接归档，并给出可撤销的提示，撤销即恢复为活跃。
- 删除需要二次确认；删除当前打开的会话会清空选择。

侧栏底部的「自动化」「已归档」切换到对应列表：「自动化」列出未归档的自动化 Chat，有未读时入口带圆点；「已归档」列出用户自己的和自动化的已归档 Chat。

全局搜索的「聊天」分组只在面板打开时读取会话列表：按标题匹配（不区分大小写），最多 9 条，活跃会话在前，选中后打开该会话。

会话区不显示消息信封头（收件人、消息类型、唤醒方式）。用户消息没有唤醒 Agent 时，气泡下方留一行原因。失败或取消的轮显示状态和失败原因，并提供「重试」「在新会话中重试」和执行记录入口；已完成轮不显示状态文字。Chat 不再显示尝试列表。重试由 Chat 的创建者发起，服务端按私聊规则放行，只接受失败或取消、且同一会话没有其他活跃轮的轮；规则见[消息接口](dev/message-api.md)。

每轮最终回复之前的过程（命令、文件改动、网页搜索、工具调用、中间说明、上下文压缩、子代理、计划）收在回复上方的执行步骤里：

- 运行中标题不到 1 秒为「处理中」，之后为「已处理 {时间}」并每秒更新，默认展开；最终回复开始输出时改为「用时 {时间}」并收起，不等这一轮结束。正在停止的轮显示「{时间} 后已停止」。运行中不再另显示状态条；状态条只在执行记录还没开始（排队、派发、离线、等待目录等）、读取失败，或等待人工回答时出现。
- 一条命令按解析出的动作各占一行（读取、搜索、列目录、运行）；模型给命令写了说明（Claude 的 Bash description）时整条命令只占一行，以说明为行文字，命令留在详情里。一个文件改动一行；连续两行以上收成一组，默认收起，摘要按固定类别顺序写成「已读取文件，运行了命令」，不显示数字。思考不单独成行，只在运行中替代「正在思考」显示思考摘要的最后一行；当前动作用静态图标加扫光，每个动作至少显示 1 秒。失败的命令仍写「已运行 …」，退出码在详情里；被引导或停止打断的命令（没来得及返回结果，或正在运行时被中止）写「已停止 …」。子代理各占一行，见下文「子代理」。
- 点开命令看到命令（超过两行时可「展开 / 收起」）、自动换行的输出（已结束的从头显示，运行中的跟随末尾，往上翻后不再跟随）和「成功 / 已停止 / 退出码 N」，命令块和输出块右上角各有复制按钮；组里有一行打开时整组不限高，详情完整显示。点开文件改动看到该文件的 diff 和增删行数。
- 已结束的轮只在完成摘要记录了过程条目时显示折叠的「用时 {时间}」，点开才读取执行记录；更早的轮不显示折叠。不论有没有折叠，「查看执行记录」都在回复下方那一行，跟在「{时间} 内回复」和复制按钮之后，和复制一样在悬停或聚焦时出现（触屏设备一直显示），折叠里没有这个入口。失败或取消的轮把折叠放在失败提示上方，执行记录入口留在提示里，一直显示；取消的轮折叠标题为「执行步骤」。
- 一轮结束（完成、失败、被停止，或排队的消息放行出下一轮）时，它运行中的步骤和回复原样留着、计时停止，等这一轮的结果进入对话（完成轮的卡片和回复，或失败、取消提示）再在同一帧换成对话里的行，最多等 4 秒；这时开始的下一轮显示在它下方，各自独立。回复不会出现后消失再出现，也不会同时显示两份。

Agent 在 Chat 里发起的权限请求和提问（AskUserQuestion）交给 Chat 的创建人回答（飞书 transport Chat 交给 bot 设置的处理成员）。原问题作为一行留在对话里；输入框上方的问题行列出本会话所有待回答的问题，以及运行中这一轮已答的问题，有没有运行中的轮都显示；点「回答问题」在右侧抽屉作答：这一轮还在等就把答案交给它，原调用已结束则在新一轮续接。Chat 的问题不经 Remi 总结，也不另开 Remi 会话；绑定飞书的 Chat 直接发原题卡片。规则见[统一问题](dev/questions.md)。

输入框右下角的圆环显示上下文窗口占用：只画环，不显示百分比，达到 90% 变红，悬停显示「已用 / 总量 · 百分比」。运行中跟随这一轮的实时上报，空闲时读取最近一轮结束时记下的占用，刷新后仍显示；一轮刚结束、它的卡片还没到时保留最后一次实时值，不回落到上一轮；没有数据时隐藏。子代理的上下文不计入这个圆环。

输入框底栏在 Agent 和工作位置选择器后面显示这个对话用的模型，只读，不能在这里切换：已开始的对话看它自己的 Agent，新聊天看当前选中的 Agent。有推理强度时接在后面，如「Opus 4.1 · High」。名称沿用 Agent 设置里模型目录的显示名，目录里没有时显示模型 ID；Agent 没指定模型时显示「默认模型」，由运行这一轮的 Runtime 决定。运行中的这一轮切换到备用模型时，改显示备用模型，图标换成切换箭头。悬停显示完整模型 ID、推理强度，并提示到智能体设置里修改。Agent 或模型目录还没加载完时不显示，加载完一次出现。它只占选择器剩下的空间：底栏变窄时名称先截断，再窄先收起推理强度，最后整个隐藏，不挤占选择器和发送按钮。

## 子代理

Claude 与 Codex 的子代理在桥的原生子会话里运行，每个子代理是执行记录里的一个 `subagent` 条目，它自己的消息和工具是嵌套条目；机制、开关与取舍见 [ADR 0021](adr/0021-subagent-sessions-and-autonomous-rounds.md)。界面一律称「子代理」，「智能体」只指用户自己的 Agent。

- **步骤行。** 执行步骤里每个子代理只占一行：「名称 · 任务首行」，右侧是状态：「运行中 {时间}」「后台运行中 {时间}」（每秒更新）、「✓ N 个工具 · 用时」（只数这一层的工具）或「✓ 已完成 · 用时」、「✕ 失败」、「■ 已停止」。整行打开子代理面板，不在行内展开，也不显示实时动态。标签以名称为主，类型（Claude 由桥补丁提供）做次要文字。给子代理发消息、打断、恢复、关闭、列出子代理是控制动作行（「已发送消息给 X」等，点开看完整消息），分组摘要为「给子代理发了消息」或「管理了子代理」；Codex 的 `wait` 不出行，也不算作过程条目。
- **折叠标题。** 后台子代理不占住这一轮：只剩后台子代理在跑、Agent 最后说完一段话时，折叠标题加「· N 个后台子代理运行中」，不强制展开；最终回复开始后，仍在运行的顶层子代理都算。
- **完成行。** 最终回复开始后才结束的顶层子代理，在回复下方各占一行：「✓ X 已在后台完成 · 用时 · 查看结果」「✕ X 在后台失败 · 查看详情」「■ X 已在后台停止 · 查看详情」；多于 3 个时只显示前 3 个，其余合并为「另有更多子代理在后台结束」（轮卡最多存 5 个，所以不写个数），打开概览。运行中的轮从实时执行记录算；已结束的轮只读轮卡的 `late_subagents`（最多 5 个），不读执行记录，没有该字段的旧轮不显示。
- **迟到的回答。** Claude 的后台子代理在这一轮的回复之前结束时，桥在 prompt 结束后再开一轮把结果告诉 Agent。daemon 在同一轮里等这次后续回答（第一帧最多 60 s），所以显示的回复是后续回答，「我已在后台启动……」成为过程说明，计时包括等待；等待中发出的引导或 wrap-up 结束等待并照常送达。
- **运行条。** 运行中的轮有子代理在跑时，消息列表顶部吸附「N 个子代理运行中」（只数顶层，没有顶层时数嵌套），后面是顶层子代理的名称、计时和「后台」标记；「+N ▾」展开运行中的子代理树和各自的实时动态。点 chip 打开该子代理的详情并展开折叠、滚到它的行。没有停止按钮。
- **侧栏标记。** 运行中的会话行在 spinner 旁显示「N 个子代理」，计数来自服务端的待处理轮列表（`GET /api/turns` 的 `running_subagents`，由 daemon 的 `task.activity` 上报），不逐个读取执行记录；旧服务端或计数为 0 时只显示 spinner。
- **入口。** 会话头的「查看子代理与后台任务」按钮（右侧面板图标）在当前会话有子代理或后台任务记录时出现，轮结束后仍在，没有记录的会话不显示。「有记录」只看页面已经有的东西，不为它另读：已加载的对话里有轮卡写着跑过子代理（完成摘要的条目统计里有子代理，或有「在后台结束」的子代理），运行中这一轮的实时执行记录里有子代理；后台任务看会话列表的运行数、已读过的后台任务登记、启动过后台任务的轮卡和「后台任务 X 已完成」那一行。所以没加载到的更早历史、记下条目统计之前的旧轮不算；早于登记保留期（7 天、每个会话 50 条已结束）的后台任务只剩轮卡，打开后看到「这个会话没有后台任务」。角标是正在运行的数量（子代理按运行条的算法，加上运行中的后台任务），为 0 时不显示，按钮的名称里也带「N 个运行中」。点它打开面板：有子代理时是整个会话的子代理概览，否则是后台任务；面板开着时再点关闭。
- **面板。** 子代理概览覆盖整个会话：每个跑过子代理的轮一组，最新的在上，组头是这一轮的时间和提示词首行（对话里送进这一轮的消息，没有时用轮的记录，都没有时打开后取执行记录里的第一条消息），运行中的组标出「N 个运行中」。最新的一轮、运行中的一轮和打开面板时指向的那一轮默认展开，其余收起，展开时才读取那一轮的执行记录；组里分「运行中 · n」（先显示 4 个）和「已完成 · n」（先显示 10 个），只列顶层子代理。点一个子代理打开它的详情：一段小对话，任务气泡、子代理自己的执行步骤、结果（运行中为「完成后在这里显示结果。」，失败显示错误，停止显示停止前的输出），以及模型和「后台」标记；返回回到概览。嵌套子代理从父子代理的详情进入，用返回按钮逐级退出。步骤行、完成行和运行条打开的面板直接到那一轮的子代理或概览。
- **面板的位置与开合。** Chat 页里面板在会话右侧挤窄会话：默认 400px，可在 320–560px 之间拖动左边缘调整（聚焦后方向键每次 16px，Home / End 到最宽 / 最窄，双击或回车恢复 400px），宽度按浏览器记住，会话至少留 352px；放不下时面板覆盖会话；窄于 768px 的屏幕是全宽抽屉；浮窗里覆盖窗口。打开和关闭是一次连续的动画：并排时面板外框从 0 宽到它的宽度（约 0.5 秒的弹性，不超出），面板内容一开始就是最终宽度，文字不随动画重排；会话一边被推开一边重排，正在看最新消息的会话始终停在底部。覆盖时面板从右侧滑入滑出（200ms）。中途再点会从当前位置折返；系统设置减少动态效果时直接打开或关闭。关闭动画结束后面板才移除，再打开时已读过的内容立即显示。
- **关闭。** × 或焦点在面板内按 Esc 关闭，焦点回到打开它的按钮或行（那一行已不在页面上时回到会话头的按钮）；切换会话或关闭浮窗时立即关闭，点会话不关闭。
- **只读。** 面板没有输入框：两个桥都不接受直接发给子会话的消息，Chat 不提供给子代理发消息或停止子代理的入口；要调整就在主对话里引导。
- **权限与提问。** 子代理发起的权限请求和提问与 Agent 自己的走同一条路径，出现在输入框上方的问题行和问题卡里，标出「来自子代理 X」；批准后子代理继续。字段见[统一问题](dev/questions.md)的 `source_subagent`。

## 后台任务

Agent 交给后台继续跑的工作（Claude 的后台命令、工作流和 MCP 后台任务，Codex 的后台终端）可以在这一轮回复之后继续运行：轮照常在回复时结束，只要还有后台任务在跑，这个会话的 Agent 进程就留在电脑上（驻留），下一轮直接接着用，开发服务器和长测试不会随轮结束被杀。机制、上限与取舍见 [ADR 0022](adr/0022-background-tasks-keep-alive-on-demand.md)；只有 Chat 会这样，Issue 的轮结束时停止它的后台任务。

- **启动行。** 执行步骤里启动后台任务的那条命令只占一行，状态取它启动的任务：「已启动后台命令 X」，会话的后台任务登记确认它仍在跑时为「X 仍在后台运行」，登记里查不到时为「X 已转到后台运行」，之后为「后台命令已完成 / 失败 / 已停止 X」；工作流和其他后台任务用「后台工作流」「后台任务」。
- **面板。** 右侧面板多一个后台任务视图，没有运行中的轮也能打开，会话头的按钮在会话只有后台任务时直接打开它。同时有子代理和后台任务时，头部是「子代理 | 后台任务 · m」切换（子代理概览覆盖多轮，未展开的轮还不知道顶层子代理数，所以不写数字）；两个视图都是整个会话的。概览顶部「后台保留到 {时间}」和「全部停止」，分「运行中 · n」和「已结束 · n」；每行是名称、类型（命令 / 工作流 / 监视）、状态和最后一行输出（结束后是原因），来自更早一轮的加「来自第 n 轮」。详情只读：命令（可复制）、实时输出末尾（Codex 没有）、摘要、开始时间与用时、「查看启动它的那一轮」，底部「后台保留到 {时间}；关闭会话或到时会停止。」。
- **运行条与侧栏。** 会话有后台任务在跑时，消息列表顶部显示「N 个后台任务运行中」（同时有子代理时「N 个子代理、M 个后台任务运行中」），没有运行中的轮也显示；chip 打开任务详情，运行条没有停止按钮。侧栏的行显示「N 个后台任务」，没有运行中的轮时旁边是小圆点而不是转圈；有运行中的轮时子代理数优先。
- **停止。** 行上的 ■ 与详情里的「停止」立即停止，不确认；「全部停止」要停 2 个及以上时先确认「停止这个会话的 N 个后台任务？」。请求发出后行显示「正在停止…」，15 s 没有变化改为「停止请求已发送，等待电脑响应」；电脑离线时提示「运行这个会话的电脑离线，暂时无法停止」。只有 Chat 的创建者能看和停止。输入框的停止按钮只停这一轮回复，会话有后台任务在跑时它叫「停止回复（后台任务会继续运行）」。
- **任务结束。** 驻留的 Claude 任务自己完成或失败时，Agent 会醒来：会话里出现居中的一行「后台任务 X 已完成 · 查看」（或「失败」），不是气泡，随后是 Agent 自己开口的回复，像普通回复一样；这时有人在发消息，消息并入或引导这一轮。Codex 不会自己醒来：它的任务在两轮之间结束时，运行条下方留一行同样的「后台任务 X 已完成」，下一轮仍能读到它的输出。Remi 自己停止的任务（到了保留时长、这台电脑同时保留的进程已满、电脑上的 Remi 重启、会话重置或关闭、智能体配置更改、进程中断）在运行条下方留一行可关闭的「X 已停止：{原因} · 查看 · ×」，10 分钟后消失；你自己停的不再重复。
- **上限。** 保留时长从会话最近一轮结束算起，默认 2 小时，每一轮都重置；一台电脑同时最多保留 4 个会话的进程，满时停掉最久没有活动的那个。
- **共享本地文件夹。** 几个 Chat 指向同一个本地文件夹（Project 的本机目录或 Runtime 工作区）时，同一时间只有一个在里面工作；保留着后台任务的会话一直占着这个文件夹，直到任务结束或到了保留时长，因为它的 Agent 可能自己醒来改文件。另一个会话的这一轮等着，状态条显示「本地文件夹正被另一个对话的后台任务占用」，那个对话在你的会话列表里时附「打开「{标题}」的后台任务」，去那里「全部停止」即可放开。默认的 Chat 工作目录彼此隔离，不受影响。
- **归档与删除。** 归档或删除会停止会话的后台任务：有后台任务时即使没有运行中的轮也先确认归档，删除确认里多一句「它的 N 个后台任务也会停止」。

当前代码里还没有侧边聊天，本节只记录已接受的设计，实现时改写为契约。设计见 [ADR 0024](adr/0024-chat-side-chat-fork.md)。

侧边聊天是从主对话「此刻」分叉出的临时 Chat，和主对话并行，互不等待：

- 没有自动删除，跟着主对话归档、恢复和删除。

## 会话与上下文

新聊天选择 Agent，首条消息或首次附件上传时创建会话。每个会话绑定一个 Agent，切换 Agent 会开始新聊天。
工作位置选择器在输入框底栏、Agent 选择器旁边，不单独占一行。新聊天默认「无项目」：在这个对话自己的目录里工作，启动时不拉取任何代码；也可改选 Project 或 Runtime 本机目录，两者互斥。首次发送或上传附件创建会话后位置固定，需要更换时新建 Chat。浮窗里已开始的会话把已绑定的位置显示为只读标签，悬停说明位置已固定；未绑定的会话不显示；独立页由会话头显示已绑定的位置。新建、打开或离开一个会话都会清空草稿位置，所以删除当前会话或再开新聊天时总是回到「无项目」；只有侧栏分组的「+」会预先带上该分组的位置。底栏变窄时，位置选择器只保留图标，名称在提示和无障碍标签里。Issue 与快速创建沿用「自动安排」，不受影响。Runtime 目录的绑定与保留规则见 [Runtime 工作区契约](dev/runtime-workspaces.md)。
选择 Project 后使用其指令、资源、Memory 和 Wiki。绑定的 Project 被归档或删除后，下一轮清除旧执行上下文，在平台 Chat 目录冷启动为纯对话；之后正常续聊。
界面显示「已绑定的项目不可用」，旧真实目录和已有仓库文件保持不动。历史列表不提供按 Agent 或 Runtime 的筛选。
Chat 与 Issue 独立：在聊天里创建 Issue 只创建工作项，不绑定会话，不继承该 Issue 的项目、仓库、附件或 Wiki 上下文。
任务领取中的只读 `chat_project_id` 来自 Chat 显式选择的项目；仅保留与该 ID 匹配的项目提示词和资源，不从历史 Issue 推导项目。
Web Chat 和飞书一对一私聊不接收 Issue 活动播报；飞书群里的 Issue 话题由飞书绑定表记录归属。Issue 最后一个在跑任务结束时（完成、失败、取消均算），系统将带触发任务 ID 的报告信封写入绑定 Chat 的会话日志，转述任务自行阅读 Issue 日志并回帖；同一触发任务的信封去重。
飞书 Issue 话题不出现在 Web/CLI 的 Chat 会话列表和待处理列表中，其讨论与更新保留在 Issue 话题入口。
升级时，缺少确定归属证据的历史群关联需要管理员按[迁移手册](migrations/chat-issue-decoupling.md)审计并恢复；恢复前暂停该关联的 Issue 通知。

会话支持重命名、置顶、归档、恢复和删除。归档会停止未完成的运行并禁止继续发送，恢复后可继续聊天。
删除会移除会话及消息，并取消未完成运行。列表提供最新消息、未读数及运行状态；置顶会话优先。

## 项目仓库与工作目录

显式选择 Runtime 工作区时，Chat 使用注册的本机目录，不附加 Project 仓库，也不自动 clone、fetch 或切换分支。
未选择任何工作位置的 Chat（「无项目」）保持纯对话，在自己的平台目录里运行，启动时不 clone 或 fetch 任何仓库，仓库按需通过 `remi repo checkout` 获取。
Project 配置了 `local_directory` 时，Chat 在该真实目录执行，启动不会自动 clone、fetch 或修改 Git 工作树；
Wiki 使用 CLI 访问，既有 `.multiremi` 任务元数据仍会更新。

同一 Project 可在不同 daemon 上配置多个目录。唯一选择规则是资源列表按 `position, created_at, id` 升序
排序后的首个 `local_directory`；路由、执行指纹、旧目录匹配和 daemon 都消费
[`selectChatLocalDirectory`](../packages/contracts/src/chat-local-directory.ts) 的同一个选择。
daemon 只校验本机是否持有所选目录，不能跳过首项改用列表里的本机目录。
已使用的选择发生变化时，已有 Chat 在 `chats/<id>` 冷启动一次，后续正常续聊；
旧用户目录保持不动，不进入替换目录。只有新建 Chat 才采用当前选择。

目录选择变化的检查清单（指纹比较所选 daemon 与规范化 path，不比较整个集合）：

| 操作 | 选择及已有会话行为 |
| --- | --- |
| 新增第一个目录，或新增排在当前项之前的目录 | 选中项变化，已有会话留在/转入托管目录 |
| 删除当前项，包括删除最后一个目录 | 选择下一项或空值，已有会话转入托管目录 |
| 调整任一项 position，使首项变化 | 新首项改变指纹，已有会话不进入新目录 |
| 同 position 下 created_at 次序变化（例如删除后重建） | 遵循资源列表的次序，与路由及 daemon 一致 |
| 修改选中项 local_path 或 daemon | 选中赋值变化，已有会话转入托管目录 |
| Project 归档、删除或不可用 | 可用选择变空，同时清除旧项目上下文 |
| Project 恢复、重新添加目录 | 托管模式保持；已有会话不重新取得用户目录权限 |
| 修改 label、非目录资源，或修改/增删/重排未影响首项的目录 | 选中赋值不变，不因此重置会话 |
| 路径仅作等价规范化、position 数值变化但首项不变 | 选中赋值不变，不因此重置会话 |

资源类型不能原地修改，类型替换通过删除再新增处理。`project_ref` 不继承本地目录。
`position` 与 `created_at` 完全相同时，以唯一资源 `id` 升序打破并列，保证重复查询的选择稳定；
调用方保持此顺序，不增加另一套排序规则。

其他绑定 Project 的 Chat 在 daemon 的 `work/<chat_session_id>` 目录运行（位于 `MULTIREMI_WORKSPACES_ROOT` 下，见[存储与保留](dev/storage-retention.md)）。
首次使用时自动拉取 Project 显式声明的 `github_repo`（包括 `project_ref` 引用），
不会因 Project 未声明仓库而自动拉取整个 workspace 的目录清单。
工作分支为 `chat/<chat_session_id>`；已有 worktree 后续轮次直接复用，保留本地改动，不重复 fetch。
需要刷新或重试失败仓库时使用 `remi repo checkout <repo-id>`。

自动同步按仓库串行执行，共享 120 秒网络预算；daemon 环境变量
`MULTIREMI_REPO_CHAT_STARTUP_TIMEOUT_MS` 可指定 1–2147483647 的整数毫秒覆盖该预算。
已有 bare cache 的刷新最多占用 30 秒，也受总预算约束。Issue 的同步预算不受此配置影响。
启动过程中 Chat 显示仓库准备进度；鉴权、网络或超时失败会保留之前成功的仓库，继续启动对话，
并在智能体提示词中记录失败原因与手动获取指引。该网络预算不包含本地 worktree 文件落盘耗时。

项目绑定在创建时固定。自动准备不会删除已有仓库，也不会覆盖同名的其他目录；
Project 资源列表变化或项目不可用时，已有工作副本保留。

## 消息与执行队列

消息写入对话日志。正在运行的轮收到定向的 now 消息会插话；pending 轮合并后续消息，领取时读取连续输入范围。同一 lane 只有一个 pending 轮。
运行中有两种后续发送方式，取舍见 [ADR 0020](adr/0020-chat-follow-up-queue-and-native-steering.md)：

- **引导**：普通发送 `POST /api/sessions/:id/messages`，`wake_requested:"now"`，行为不变，送进正在运行的这一轮。Claude 与 Codex 的 daemon 用桥的原生引导把它注入正在进行的 prompt，不打断正在运行的命令（Claude 等当前工具调用结束后再注入，最多 30 s）；桥不支持、出错、这一轮恰好结束，或有待回答的权限或提问卡片时，退回到中止当前 prompt 后在同一会话重新提示（[ADR 0020](adr/0020-chat-follow-up-queue-and-native-steering.md)“原生引导”）。未读消息可用 `PATCH`/`DELETE /api/messages/:id` 编辑或删除，已进入轮输入的返回 409；编辑和删除留下日志标记。
- **排队**：`POST /api/sessions/:id/queue` 把消息存进服务端队列表，不写对话日志。条目按入队顺序一次放行一条，与 Codex 一致：lane 没有 pending、running 或 awaiting_human 轮且未暂停时，入队立即放行最早的一条；否则在当前轮 completed 的终态事务里放行下一条，其余继续排队，等这一条开启的轮 completed 再放行下一条。放行的条目转成普通成员 now request，建 pending 轮、正文内联，排在本轮回复之后进入日志；这一轮没读到的 now 消息仍合并进同一个 pending 轮。

排队的条目只有原发送人能改：`PATCH .../queue/:qid` 可带 `expected_revision`，`DELETE` 幂等，`POST .../queue/:qid/steer` 立即放行这一条（改为引导，重复调用返回同一条消息）。
已被轮放行的条目再改或引导返回 409 `queued_message_consumed`，版本不符返回 409 `revision_conflict`，归档的 Chat 入队、引导和继续返回 409。每个 Chat 最多 50 条未放行条目，每条最多 10 个附件。

队列会暂停。`interrupted` 与 `send_failed` 期间轮结束也不放行；`turn_ended` 在该 lane 下一次有轮 completed 时自动解除并放行：

| 原因 | 触发 | 解除 |
|---|---|---|
| `interrupted` | 成员停止当前轮（`POST /api/turns/:id/cancel`） | 只由 `POST .../queue/resume` 解除，期间轮 completed 也不放行 |
| `turn_ended` | 轮 failed，或被成员以外的身份（agent、supervisor 等）取消 | 该 lane 任一轮 completed（包括失败轮重试成功、之后的直接发送完成）时自动解除并放行；或 resume |
| `send_failed` | 放行某条失败；该条标为 failed，后面的条目不越过它 | resume，或编辑、删除、引导该条后不再有 failed 条目 |

resume 清除暂停、把 failed 条目重置为 queued，lane 空闲时放行最早的一条；队列为空时暂停自动清除。
归档时被取消的轮既不放行也不暂停；恢复后条目保留，resume、下一次入队或下一轮 completed 时放行。`wake=next_turn` 的含义不变，仍不会单独补铃。
Web 输入框运行中按偏好（设置 →「偏好」→「聊天」，默认排队，与 Codex 一致；浏览器里已保存的选择优先）发送：↵ 换行，⌘↵ 用偏好的方式，⌘⇧↵ 这一条换用另一种；空闲时都是普通发送。输入框只有一个主按钮：空闲时是「发送」；运行中输入框为空时是「停止」，有内容时是向上箭头，名称为 ⌘↵ 会采用的「排队」或「引导」；编辑排队消息时是「保存」。运行中在输入框里连按两次 Esc（2 秒内）也会停止当前运行，输入框有内容时用它停止，草稿保留。偏好为排队时，在空输入框按 ⌘⇧↵ 引导第一条可引导的排队消息，焦点留在输入框；⌘↵ 在空输入框不做任何事。排队的消息显示在输入框上方的队列里，可逐条引导、编辑（载入输入框，保存时带 `expected_revision`）或删除（5 秒内可撤销）；暂停时显示原因和「继续」。没有 API 应答（网络错误、超时或网关 408/502/503/504）的排队请求标为无法确认送达，不自动重试。前端实现见[前端开发上下文](dev/frontend.md)。

收尾用 turn wrap-up，取消用 turn cancel，重试在同一轮新增 attempt。取消不撤销已执行的工具操作。
输入框在提交时清空，草稿跟随正在显示的会话；服务端拒绝发送时正文放回输入框，删除失败时保持会话选择。消息在服务端接受时即显示「已发送」；20 秒没有应答、网络错误或网关应答时显示「未确认送达」并重读会话日志确认，重试复用同一 dedupe_key，不会重复发送。

聊天记录与 provider 会话是两层状态。正常续接复用既有运行上下文，输入范围从当前 agent lane 的实际读游标开始，
包含尚未读取的请求和编辑后的 next_turn 正文，过滤已删除消息；无法续接时，Remi 使用有预算的聊天历史投影，
截断会被标识。不能据此承诺每轮携带完整历史或底层工具的全部工作记忆。

内部恢复入口可为尚无已完成谱系的首轮显式提供 Runtime、provider session 与工作目录；领取时保留这些初始值，后续用户轮使用已完成的 Chat 谱系。飞书 transport 的亲和性仍按其绑定刷新。

只读飞书 Issue 话题保留所属 Project 的仓库展示目录，自动 checkout 仍使用独立的显式仓库清单。

自动终态回复发给 Chat 创建者的工作区成员，成功结果和最终失败均进入该成员的收件箱。
Chat 列表的未读计数使用同一 member lane；读到较早消息保留最终回复未读，读到回复后清零。

## 斜杠命令

一对一私聊里，以 `/名字` 开头的消息原样作为这一轮的开头发给 agent，由它的 ACP 桥执行，例如 Claude 的 `/compact`、`/init`、自定义命令和技能，Codex 的 `/review`、`/compact` 和 `$技能`。命令只在消息开头才执行；带发言人标签的消息（群聊、飞书话题、Issue）里不执行。设计见 [ADR 0025](adr/0025-chat-slash-commands.md)，已实现的部分：

- **拦截。** 少数命令在托管的运行机器上有害或没有意义：会动到运行机器主人的账号或设置，或绕过 Remi 换模型。daemon 不让桥执行它们，而是在消息前加一行 `[Remi] The user typed the command /<名字>, which Remi does not run here. It reached you as text and did not run.`，原文接在后面，模型据此说明。名单按 provider 区分，在 [slash-commands.ts](../packages/contracts/src/slash-commands.ts)：Claude 的 `/remote-control`、`/model`、`/effort`、`/fast`、`/config`、`/clear`、`/usage`、`/login`、`/logout` 等（含它们的别名），Codex 的 `/logout`、`/status`，Antigravity 的 `/logout`、`/usage`。插话文字同样处理。
- **`/compact`。** 两个桥执行压缩时都不回复文字。这一轮输入是 `/compact`、看到了压缩、且没有插话或自主轮时，轮正常完成，回复是 `Context compacted.`，压缩步骤照常显示；其他「只有压缩、没有文字」的轮仍判为空输出失败。
- **技能名。** Remi 安装的平台技能以目录名作 `SKILL.md` 的 `name`，例如「Git Commit」用 `/git-commit`（Codex 用 `$git-commit`）调用。
- **命令目录。** 每轮结束时，daemon 把 agent 最近一次发布的命令列表随终态报告带回，存在这个 Chat 的 agent 会话线上（协议见 [daemon 协议](daemon-protocol-v2.md)）；Remi 这一轮装下的平台技能带上 `skill_id`。`GET /api/chat/slash-commands?agent_id=&session_id=` 返回菜单要显示的命令，被拦截和隐藏的已去掉：`state` 为 `session`（这个 Chat 自己报过的，空列表也算）、`preview`（还没报过时，用请求者自己和这个 agent 最近一次对话的列表，provider 和 Runtime 都要与 agent 现在的一致）或 `none`（旧 daemon 从不上报）。带 `session_id` 时只有 Chat 的创建人能读，与读这个 Chat 相同；只带 `agent_id` 时要求能和这个 agent 聊天。Claude 对 `/context` 这类不调模型的命令会把同一段输出发两次，provider 只保留第一份。
- **「/」菜单。** 只有「/」是整条消息的第一个字符时才打开，用的是这个对话自己的 agent（已有对话用会话的 agent，新对话用所选的 agent）。分两组：「Agent 命令」是上面接口返回的命令，「技能」是这个 agent 在 Remi 上配置的技能，桥发布的同一个技能（相同 `skill_id`，不按名字）并进技能那一行。`preview` 时注明来自你和这个 agent 的上一次对话；`none` 时只有技能，并提示 Agent 命令会在第一次回复后出现；读取中和读取失败各有一行说明，不显示成空列表。命令列表在这个对话里第一次打开菜单时才读，之后每轮结束（`chat:done`、`task:failed`）刷新。
- **匹配和键盘。** 依次按名字完全相同、前缀、单词开头、包含、说明包含排序，组的顺序不变。只有完全相同或前缀匹配时默认选中第一项，Enter 或 Tab 插入；只是较弱的匹配时不选中，Enter 保持原来的作用（Chat 里是换行）。Mod+Enter 总是发送，输入法组字时不处理按键。
- **插入的内容。** 选中后插入一个命令标签和一个空格，标签发出去就是调用文字本身：`/compact`、技能的 `/deploy-prod`，Codex 的技能是 `$deploy-prod`，不再是 `slash://skill/` 链接。参数提示只在菜单里和标签后面灰色显示，不进正文。草稿重新载入后标签变回普通文字，发送内容不变。
- **运行中排队。** agent 正在运行时，以命令开头的消息一律排队，不插话，按钮提示命令会在本轮结束后执行；Mod+Shift+Enter 也不会让它插话。
- **被拦截的命令。** 手动打出上面拦截名单里的命令时，输入框下方提示 Remi 不会执行它、agent 只会收到文字，仍可发送。
- **对话记录。** 用户消息开头的命令显示成标签，其余照常；旧消息里的 `[/名字](slash://skill/<id>)` 照旧显示成标签。

## 权限与实时更新

直接聊天仅创建者可读写，另需满足工作区成员与 Agent 访问条件。其他工作区成员及管理员不能读取别人的私聊。
消息范围读取 `messages?from&to`、单条展开 `log/entry`、定位 `log/locate` 和 `log` 窗口允许任务凭据读取自身绑定的 Chat，
前提是任务、凭据与 Chat 的工作区一致；飞书个人机器人 Chat 同样适用。任务凭据访问同工作区其他 Chat 返回 403，
即使目标创建者是凭据中的用户或 Runtime owner，也不回退到创建者权限。未绑定且不存在的会话同样返回 403；
已删除的绑定 Chat 与跨工作区 Chat 返回 404。人类 PAT/JWT 仍沿用创建者访问规则。
范围读取按凭据中的 agent 记录实际已读进度，定位、窗口和单条展开不推进该进度。
消息、附件、task transcript 和实时订阅各自保留对应权限检查，不能只依赖页面隐藏。
任务详情与控制接口、Agent 任务列表同样检查私聊权限；Issue 分享不包含 Chat 的输入与执行记录。
删除会话后，留存任务继续保留私聊标识以拒绝读取，也不能通过复用旧会话 ID 重新取得这些记录。
工作区选择沿用服务端统一解析规则：显式工作区参数优先，其次为请求头和凭据绑定的工作区。
聊天列表、创建和待处理任务在解析工作区后继续校验成员权限；未知 slug 不回退到 `local`。

服务端数据由 Query cache 管理，草稿和选择由工作区分区的 store 管理。WS 更新保持当前执行任务与后续队列分离，
取消某条排队消息不能清除另一条正在执行任务的状态。队列的每次变更、放行和暂停在提交后发送 `chat:queue_updated`，只推给该 Chat 的创建者；放行的消息经普通日志流到达。
后台任务（PR 6）同样只属于创建者：会话的后台任务读取与停止只有创建者可用，登记表的变化在提交后发送 `chat:background_tasks`，
只推给该 Chat 的创建者；接口、事件与 daemon 帧见 [daemon 协议](daemon-protocol-v2.md)的「后台任务」。
已上传附件的草稿绑定与文本一起按工作区保存，切换浮窗、独立页或会话后仍可发送。

## 归档、来源与自动化 Chat

Chat 是 daemon 存储模型里的一类主体（见[存储与保留](dev/storage-retention.md)）：被归档即视为结束，工作区按保留期回收，置顶的 Chat 不回收。
活跃 Chat 超过工作区设置 `chat_idle_days`（默认 14 天，0 为不自动归档）没有新消息会被自动归档；归档的 Chat 收到新消息（成员、飞书或自动化续接）自动恢复活跃。
`run_only` 自动化每次运行新开一个 Chat，带 `origin: { autopilot_id, run_id }`；agent 判断没有值得报告的内容时执行 `remi automation quiet`，运行完成后该 Chat 自动归档，否则保持活跃并带未读。
Chat 列表默认只显示用户的对话，`origin=automation|all` 或 `remi chat list --origin automation|all` 查看自动化开的 Chat；独立页侧栏通过底部「自动化」入口查看。
